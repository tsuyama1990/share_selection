# 一次スクリーニング基準：原著との照合と改修方針

最終更新：2026-10-13（実装状態を反映）

このリポジトリが受け持つのは、投資フロー全体のうち **Step 1（一次スクリーニング：割安・健全フィルター）** だけである。二次スクリーニング（レイヤーマスター探し）、格差の判定、記録と検証（Step 2 以降）はこのリポジトリの範囲外。

## 根拠にしている2つの資料

| 略称 | 資料 | 一次スクリーニングに求める役割 |
|---|---|---|
| 原著 | エミン・ユルマズ『エミン流「会社四季報」最強の読み方』 | 割安とクオリティ（財務）を兼ねる銘柄を選ぶ。下値の余地を重視する |
| 手法書 | レイヤーマスター投資フロー：期待の修正を取る再現手順（Claude Docs） | 期待がすでに低いこと、稼ぐ力があること、高金利に負けないことを保証する。下値を守り、二次の候補母集団をつくる |

基準が食い違うときの原則：**足切りは下値の安全のためのもの。原著の観点は出力列（指標）と二次の調査で表す。** 加点（Total_Score・Recommendation_Type）は 2026-10-14 に廃止し、順位は改善区分 → 改善の大きさ÷株価 → 実質PSR で付ける（`docs/selection_tuning.md`）。

### 改善の兆し（選定フロー段階 2、2026-10-14 実装）

| 出力列 | 内容 |
|---|---|
| `EPS_Q_YoY(%)` | 直近四半期 EPS（希薄化後）の前年同期比。前年同期 EPS が 0 以下なら空欄 |
| `OI_YoY(%)` | 年次営業利益の前年比 |
| `Op_Margin_Change(pt)` | 年次営業利益率の前年差 |
| `Improvement_Class` | **四半期優先**：前年同期と比較できる新しい四半期 EPS があればそれだけで判定（≥ `improvement.clear_threshold` 40% → clear、≥ 0 → signal、それ以外 → none。前年同期が赤字なら、黒字転換 → clear、赤字縮小 → signal）。なければ年次営業利益で同じ判定。どちらもなければ unknown |
| `Improvement_Yield(%)` | 改善の大きさ÷株価：四半期 EPS の変化×4÷株価（四半期で判定した場合）、または営業利益の変化÷時価総額。伸び率と違い、小さな基準値で膨らまない |
| `Priority_Rank`・`Stage2_Candidate` | 区分 → Improvement_Yield の大きさ → 実質PSR の低さの順位。旗（`Quality_Flags`）のない clear を順位の上から `selection.candidates_n` 件、二次の候補にする |
| `Quality_Flags` | 四半期 EPS で clear になった銘柄の一時的損益の疑い：`oi_divergence`（年次営業利益が減少）、`quarter_spike`（四半期 EPS ≥ 年度 EPS × `quality.max_quarter_share_of_annual` 0.5）。旗のある銘柄は二次候補から外す |

足切りで落ちた銘柄も含め、キャッシュのある全銘柄について計算し、実行記録（`screen_results`）に残す。最新四半期が株価データの最終日より `improvement.max_quarter_age_days`（200 日）以上古い場合は、それ以降の四半期が欠けているとみなし、四半期 EPS では判定しない。

### yfinance では取れない（四季報を手で読む部分として残す）

- 業績の2期予想（今期・来期）
- 【海外】売上比率、部門別の売上と利益率
- 記事の注目ワード（最高益、初、トップ、底打ちなど）、巻頭ランキングのセンチメント
- 従業員の平均年齢・平均年収、大株主の顔ぶれ（個別の株主名）、外国人持株比率

補足 [データ：2026-10-13]：大株主の保有比率（`heldPercentInsiders`）と浮動株数（`floatShares`）、四半期 EPS は yfinance で取得できる。決算発表予定日は JPX の公式 Excel で取得できる（`docs/selection_flow.md`）。

これらは二次スクリーニングで、四季報の記事や一次情報を読んで確認する。

## 決定事項（2026-10-13）

| 項目 | 決定 | 理由 |
|---|---|---|
| 自己資本比率の足切り | **50%以上** | 原著の最低基準に合わせる |
| 営業利益率の足切り | **5%以上**（2026-10-13 は 7%、2026-10-14 に見直し） | 5〜7% の帯は下値が悪化しない（`docs/selection_tuning.md` 3.3） |
| PSR の足切り | **1.2倍以下**（2026-10-13 は 2 倍、2026-10-14 に見直し） | 最悪ケースの下落が縮み、1.0 と違って過去の勝ち銘柄を残す（`docs/selection_tuning.md` 3.2・3.4） |
| 売買代金の足切り | **直近60営業日の平均が3,000万円/日以上** | 数十万〜数百万円の注文を現実に約定できる流動性を確保する |

時価総額の下限は 30 億円以上（`market_cap_min`）。加点は 2026-10-14 に廃止した。

## 判断の誤りの記録（2026-10-13）

1. **NET-NET の定義変更**：「現金 ÷ 時価総額」は原著どおりの基準だった。それをグレアム流の NCAV に置き換えてしまい、のちに原著の定義へ戻した。
2. **コロナ安値比較の削除**：原著の第2章「どこまで下がるかを考える」に根拠があった。旧実装（安値の±20%以内なら加点）は原著の意図と違っていたので、加点なしの出力列として作り直した。
3. **月足の日付のずれ**（修正済み）：yfinance の履歴はアジア/東京時間（JST）の時刻だが、キャッシュ（JSON）にはUTCで保存されるため、読み戻すと月初のバーが前月末 15:00 になっていた。リーマン・コロナの安値の期間が1か月ずれ、月足の移動平均も前月側に寄っていた。キャッシュの読み出し時に `system.market_timezone`（`Asia/Tokyo`）へ変換して日付だけにするよう直した。既存のキャッシュはそのまま使える（取得し直し不要）。
