# Tailwind Watch（追い風ウォッチ）：PEST の流れの判断を支える調査

作成：2026-10-18 ／ 状態：**実装済み（2026-10-18）**。設計は `docs/architecture/L1_architecture.md` C9・`L2_C9_tailwind.md`（流れの調査）、`L2_C4_stage2_research.md`（Value Turn への追加）

月 1 回の今の仕組みは **Value Turn（割安改善スクリーン）**、本書の手法は **Tailwind Watch**。根拠の表記は `docs/hypothesis_map.md` と同じ。

## 1. 目的と方針

**目的**：PEST（政治・経済・社会・技術）の流れから、利益が決算に出る前に、恩恵を受けてまだ割安な会社を見つける。

**方針**（2 章の学びから。2026-10-18 ユーザー了承）：機械の合図で先回りはしない。次の 2 つを作る。

| | ① Value Turn への情報の追加 | ② 流れの調査（本体） |
|---|---|---|
| 中身 | Value Turn の調査メモに、追い風の記録と業種の状況を載せる | 人が指定した流れについて、引用つきの調査メモを作り、人の判断を記録し、後で答え合わせする |
| 選ぶのは | Value Turn のまま（追加は判断材料だけ） | 人 |
| 指標 | Value Turn の判定 | Value Turn の判定と PBR・PER・PSR |

## 2. 学び（2026-10-18 の検証）

詳しい数値と定義は git の履歴（コミット `646070c` の本書の付録 A.1〜A.12）にある。

1. **機械の合図での先回りは効かなかった** [データ]：公式の出来事の確定日で入ると 5 件すべて 1 年で市場に負けた。上方修正の急増は業種でも会社でも時点の効果が無い。日本株の勢いは 3 か月だけ効き、長く持つと戻る。業種がまとめて上がったときの、まだ上がっていない割安株は 6 か月 +2.5%（t 1.56）と小さく、閾値を変えると消え、最悪 −31%
2. **効くのは実際の売上・利益の伸び** [データ]：過去の 16 の流れで、恩恵企業の売上が実際に伸びたかだけが結果を分けた（相関 +0.73）。流れの始まりから 9 か月後に決算で見えた売上の加速は、その後 24 か月を予測した（+0.50、p 0.050）が、全銘柄では関係が無い。始まりの時点の会社の売上予想では予測できない
3. **同じ向きの出来事が重なる流れは年単位で効き、一度きりの需要は効かない** [データ]：防衛（予算と海外の圧力）は 3 年半で +79.7%、利上げ後の銀行は +63.3%。新紙幣・自治体システム・省エネ基準は前後とも負けた
4. **株価は公式の出来事より 5〜11 か月早く動き、第一想起の会社は先に上がって後で負ける**（業種で 6 か月 −6.2%）[データ]
5. **割安は流れの中でも効くが、全銘柄で割安を選ぶのと同じくらい** [データ]
6. **先回りが当たった事例は、複数の材料をつなぐ判断だった**（`portfolio_arena` のフジクラの事例）[データ：`portfolio_arena` の記録]。情報の非対称性は「早く知ること」より「つなげて判断すること」にある [推論]
7. **データの注意** [データ]：TDnet の閲覧ページは自動取得を断っている（robots.txt）。Yahoo のキャッシュの四半期データは EPS だけ（売上の前年比は `info.revenueGrowth`、正確さは未照合）。`portfolio_arena` の J-Quants の株価表（〜2026-06-12）には同じ値の重複行と優先株のコードがあり、`select distinct` と末尾 0 のコードに絞る

Value Turn の仮説との関係（`hypothesis_map.md` 0 章）：流れは改善の源泉（H1a）、第一想起でない割安な会社は織り込まれていない会社（H2a・H2e）、売上の伸びが決算に出ることが明るみに出るきっかけ（H3a）にあたる [推論]。

## 3. ① Value Turn への情報の追加

二次調査の業種の比較（`sector.py`）と調査メモに 2 項目を足す。選ぶ条件は変えない。設計は `L2_C4_stage2_research.md`。

| 項目 | 内容 |
|---|---|
| 業種の勢い | 候補の会社の 33 業種の直近 3 か月の超過リターン（全銘柄の等加重に対して）と、全業種の中の順位 |
| 業種の中の位置 | 候補の会社の直近 3 か月の上昇が、同じ業種の中で上から何割目か |

追い風の記録（T1 の source_type・demand_wave・tier）は既にある。メモには事実だけを書き、「先に上がった会社はその後負けやすい（有意ではない）」と注記する。

## 4. ② 流れの調査

**入力**：人が指定する流れ（名前、需要の説明、任意で出典の URL）。例：「情報流出の続発による、企業のセキュリティ対策の支出の増加」。

**調査メモ**：

| 節 | 中身 |
|---|---|
| 5 つの軸 | 下の表。軸ごとに照合できた引用と数値だけを並べ、点数は付けない。分からないことは「不明」 |
| 恩恵企業の地図 | 需要に売っている会社（何次の供給元か、売上に占める割合、引用）。全銘柄の有価証券報告書の「事業の内容」から探す |
| 会社ごとの数値 | Value Turn の判定（通過／落ちた条件、改善区分）、PBR・PER・PSR と業種の中央値、直近 3 か月の上昇と地図の中の位置、最新の T1 の需要の波 |
| 終わりの手がかり | 期限、特需の一巡、逆向きの出来事 |

**5 つの軸**（決まったベストプラクティスは見つからなかったため、政策の不確実性・注目度・物語の広がりの研究の考え方をもとに整理した [推論]）：

| 軸 | 問い | 効き方 |
|---|---|---|
| 規模 | どれだけのお金が流れるか（予算額、市場規模、業種の売上との比） | 売上 |
| 強制と裾野 | 誰が対応せざるを得ないか（法令・取引先の要求・保険の条件）、どこまで広がるか | 売上 |
| 持続 | 何年続くか、同じ向きの出来事が重なるか | 両方 |
| 注目の広がり | どれだけの投資家が気づいているか（報道、関連銘柄の株価） | 期待 |
| 織り込み度 | もう値段に入っているか（割安さ、先に上がった会社との差） | 期待 |

**決まり**：主張は取得した文書の引用で照合する（L1 N3）。二次的な恩恵の推定は人の判断材料にとどめる。情報源は公式で利用条件上取ってよいものだけ（L1 N7）。1 つの流れに入れる金額は小さくし、上限を判断と一緒に記録する（学び 1 の最悪 −31%）。

**判断の記録と採点**（記録を始める前に決める）：

| 項目 | 定義 |
|---|---|
| 記録 | （流れ, 会社, 買う／見送る, 理由, 金額の上限, 日付）。見送るも記録する |
| 結果 | 判断の翌月から 6・12 か月の、全銘柄の等加重に対する超過リターン（`evaluate`） |
| 比べる相手 | 判断の月に、同じ業種で「直近 3 か月の上昇が中央値以下、かつ PBR が中央値以下」の会社（機械の合図。学び 1） |
| 止める基準 | 「買う」が 10 件以上たまった時点で比べる相手に負けていれば、流れの調査をやめる |

## 5. 作る順番

1. ① Value Turn への追加（L2 C4 → テスト → 実装）
2. `profiles`（全銘柄の「事業の内容」の取得）と会社の地図。既知の恩恵企業を拾えるかで確かめる
3. 流れの調査メモ（`flow-memo`）。最初の数件のメモを人が採点して引用の質を確かめる
4. 判断の記録（`flow-decide`）と `evaluate` の拡張

各段階は `docs/architecture/process.md` の手順（設計 → テスト → 実装、関門つき）。
