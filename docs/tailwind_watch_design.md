# Tailwind Watch（追い風ウォッチ）：週 1 回の PEST の確認（設計の方針・引き継ぎ）

作成：2026-10-18 ／ 改訂：2026-10-18（検知の設計を全面的に作り直し、ユーザー承認。11 章の未決事項あり） ／ 状態：**方針はユーザー決定。設計（L1〜L3）と実装は別のセッションで行う**

名前：月 1 回の今の仕組みは **Value Turn（割安改善スクリーン）**、本書の週 1 回の手法は **Tailwind Watch（追い風ウォッチ）**（2026-10-18）。

根拠の表記は `docs/hypothesis_map.md` と同じ（[原著] [一次] [報道] [データ] [推論]）。この文書は方針と根拠と未決事項をまとめたもので、実装の設計ではない。実装は `docs/architecture/process.md` の手順（L1 の要件 → L2 → L3 → テスト → 実装、各工程に関門）で進める。

## 1. 目的

今の仕組み（Value Turn、月 1 回、エミン氏の手法がもと）は、**決算に出た営業利益の改善**を拾う。出来事による需要の変化（PEST：政治・経済・社会・技術）を先回りする道が無い。週 1 回、半年以上効きそうで確度の高い PEST を拾い、それに乗る会社がエミン氏の足切りを通るかを確かめて通知する。

## 2. 考え方の整理（2026-10-17〜18、ユーザーとの議論で合意）

| 項目 | 内容 |
|---|---|
| 物差し | **営業利益の改善**をリターンの中心の条件とする。事例では、営業利益が明確に増えた 15 銘柄のうち 13 が TOPIX に勝ち、増えなかった 6 銘柄は全敗 [データ：`hypothesis_map.md` 2 章、2026-02→10] |
| PEST の位置づけ | 営業利益を押し上げる要因のひとつである可能性が高い [推論]。勝った銘柄には追い風型（P1：エブレン、シグマ光機、新報国、新日本空調、FFRI、綜研化学）も自力改善型（P2：住友大阪セメント、東洋水産、住友ベークライト、artience）もある [データ]。追い風は必要条件ではない |
| Value Turn（エミン氏の手法がもと） | 決算に出た改善を確認してから買う。PEST にはとらわれない（遅いが外れにくい） |
| Tailwind Watch | PEST から改善を予想して先回りする（早いが外れる危険がある） |
| 組み合わせ | PEST で先に気づき、エミン氏の足切り・二次調査で絞る。最終判断は人 |

ダイコク電機・東天紅が上がらなかったのは、テーマが無かったことと利益が減ったことが同時に起きており、2 社だけではどちらが効いたか分けられない [推論]。

## 3. 運用の形（ユーザー決定）

| 頻度 | 中身 | 出力 |
|---|---|---|
| 月 1 回 | Value Turn：一次（足切り・改善・順位）→ 二次（LLM の調査）→ 調査メモ（今の仕組みのまま） | 候補とメモ。好きなものがあれば買う |
| **週 1 回** | **Tailwind Watch**：① 半年以上効き確度の高い PEST を拾う → ② 恩恵を受ける会社を特定 → ③ Value Turn の一次（足切り）を通す → ④ 通れば二次を通す | ③ を通れば**通知**。④ も通れば**その旨を通知**。③ で落ちた会社も、落ちた条件つきで載せる（割安の基準 PSR 1.2 倍以下で落ちるテーマ株が多いため、人が判断できるように） |

## 5. 設計の原則（事実から導く）

| # | 原則 | 理由 |
|---|---|---|
| D1 | **原因の側で気づく。** 数値の結果（修正・決算・株価）は早い合図に使わない | F1・F3・F4：結果の数値は株価と同時か後に出る [推論] |
| D2 | **確度と期間は、制度の段階と期限で決める。** LLM は文書から段階・期限・対象を引用つきで抜き出すだけで、確度・期間の判断はしない | 段階（パブリックコメント → 閣議決定 → 公布 → 施行）と期限は一次情報に日付つきで載っている。LLM の判断より再現できる [推論] |
| D3 | **恩恵の会社は全銘柄から探し、足切りで「まだ気づかれていない」会社に絞る** | F2：目立つ会社は割高。足切りを通る会社が Tailwind Watch の価値 [推論] |
| D4 | **二次的な恩恵の推定は人の判断の材料にとどめ、自動で通知の条件にしない** | F5 |
| D5 | **追い風には終わりがある。終わり（期限・特需の一巡）も追う** | F8：改刷特需の一巡で減益の例。制度の追い風は期限で終わる日付が分かる [推論] |
| D6 | **公式で、利用条件上取ってよい情報源だけを使う** | F6・F7 |
| D7 | **過去の統計で証明できない部分は、前向きに記録して後で採点する。** 採点の条件は記録を始める前に決め、日付ずらしの検証を入れる | 出来事は数が少なく、過去の選び方に後知恵が入る。F4 の教訓 |
| D8 | **既にある部品を使い、新しく作るのは出来事の台帳と会社の地図だけにする** | F8 と既存の文書取得・足切り・二次調査（7 章） |

2026-10-18 のユーザー決定「期間と確度の判定は LLM に、出典の逐語の引用つきで行わせる」を D2 で置き換える（**2026-10-18 ユーザー承認**）。「期間が半年以上かつ確度が高いものだけを通知する」は変えない。

## 6. 仕組み

### 6.1 全体の流れ（毎週）

| 段 | 名前 | 入力 → 出力 | 新規か |
|---|---|---|---|
| ① | 取り込み | 官公庁の一次情報 → 新しい文書の一覧 | 新規 |
| ② | 選別 | 文書 → 「需要を変える制度の出来事」か（LLM、引用つき）。該当すれば構造化した項目（6.3） | 新規（引用の照合は既存） |
| ③ | 台帳 | 出来事を 1 件にまとめ、段階が上がるたびに日付を記録する | 新規 |
| ④ | 地図 | 需要 → 全銘柄の有価証券報告書の「事業の内容」から候補 → LLM で確かめる（引用つき、何次の供給元か） | 新規（文書の取得・照合は既存） |
| ⑤ | 足切り・二次 | 候補 → Value Turn の一次（足切り）→ 通れば二次 | 既存 |
| ⑥ | 通知 | ⑤ の結果 → 週 1 回の通知。足切りで落ちた会社も条件つきで載せる | 新規（小さい） |
| ⑦ | 追跡 | 地図に載った会社の、その後の T1 の需要の波・決算・株価 → 「数字に出始めた」「終わりが近い」の通知 | 新規（既存の記録を読む） |

### 6.2 取り込む情報源

| 情報源 | 段階 | 取り方 | 確認 |
|---|---|---|---|
| e-Gov パブリックコメント（募集） | 案 | RSS `pcm_list.xml` | 取れた（付録 A.2） |
| e-Gov パブリックコメント（結果） | 確定（省令・告示・指針など） | RSS `pcm_result.xml` | 取れた |
| 首相官邸の閣議案件 | 閣議決定（法律案・政令・基本方針・予算） | 日付ごとの案件の一覧のページ | 一覧は取れた。案件の本文の取り方は未確認 |
| 予算（概算要求 8 月末、補正 11〜12 月、当初 12 月） | 予算 | 財務省・各省の公表資料 | 未確認（年に数回なので手作業でもよい [推論]） |
| 官報（法律・政令の公布） | 公布 | 官報の公開ページ | 未確認 |
| 米国 Federal Register | 海外の規則（関税・輸出規制など） | 公式 API（JSON） | 取れた。最初は対象外（9 章） |
| 審議会の資料・報道・TDnet | 議論・事件 | — | 最初は使わない。② で拾えなかった出来事を後で調べる材料 |

段階の順（D2）：議題・報道 → **案（パブリックコメントの募集）** → **確定**（パブリックコメントの結果、閣議決定、予算の成立）→ 公布 → 施行 → 期限。通知（6.5）は「確定」以上。

### 6.3 出来事の項目（台帳の 1 行）

| 項目 | 内容 | 決め方 |
|---|---|---|
| 出来事 | 何が決まったか（1 文） | LLM（引用つき） |
| 需要 | 誰に何の支出が増えるか（例：自治体に基幹システムの移行） | LLM（引用つき） |
| 強制の種類 | 義務・補助金や予算・推奨のどれか | LLM（引用つき） |
| 対象 | 誰が対象か（全上場企業、自治体、一定規模以上の事業者など） | LLM（引用つき） |
| 段階と日付 | 6.2 の段階ごとの日付 | 情報源の日付（機械） |
| 期限 | 施行日・経過措置の終わり・予算の年度 | LLM（引用つき）。引用が無ければ空 |
| 期間 | 確定の日から期限まで | 計算（機械） |
| 確度 | 強制の種類と段階から表で決める（例：義務かつ確定以上は高） | 規則（機械）。表は L2 で決める |
| 出典 | 文書の URL・日付・引用 | 機械 |
| 同じ出来事のまとめ | 案と結果、閣議決定と公布を 1 件にする | LLM の候補を人が確かめる [推論：自動で正しくまとめられるかは未確認] |

### 6.4 会社の地図（④）

- 全上場企業の、最新の有価証券報告書の「事業の内容」（と「経営者による分析」）を文書ストアに持つ。年 1 回の取り直しと、新しい報告書の差分 [推論：全社で約 3,700 件。取得の時間は L2 で見積もる]
- 出来事の需要に近い会社を、まず取りこぼしの少ない方法で多めに拾い（全文の検索か埋め込みの検索。L2 で決める）、LLM で「その需要に売っているか」「何次の供給元か」「売上に占める割合」を引用つきで確かめる（T1 と同じ項目）
- 確かめられた会社だけを地図に載せる。何次かは載せるが、二次以下を自動で通知の条件にはしない（D4）

### 6.5 通知（⑥）

- 対象：確度が高く、期間が半年以上の出来事（ユーザー決定）の、地図に載った会社
- 中身：出来事（段階・期限・引用）、会社ごとの足切りの結果（落ちた条件つき）、二次を通ったか
- 「数字に出始めた」（⑦）と「期限まで半年を切った」（D5）も通知する

### 6.6 追跡（⑦）

- 地図に載った会社が、その後の Value Turn の二次調査（T1）で同じ需要の波を挙げたか。既存の `reviews` を読むだけ
- 地図に載った会社の決算の営業利益（キャッシュの財務）と株価（週 1 回）
- TDnet の文章（理由）は、取得の経路が決まるまで使わない（9 章）

## 7. 採点（記録を始める前に決める）

| 項目 | 定義 |
|---|---|
| 単位 | （出来事, 会社）の組。通知した組も、通知しなかった組（確度・期間が足りない、地図で落ちた）も記録する |
| 結果 1：利益 | 出来事の確定から 2・4 四半期後の営業利益の変化（前年同期比） |
| 結果 2：株価 | 確定の翌週から 6・12 か月の TOPIX に対する超過リターン |
| 比べる相手 | 同じ業種で、足切りの結果が同じで、地図に載らなかった会社 |
| 日付ずらし | 確定の日を ±6 か月ずらした超過リターン。実際の日付より小さくなければ、時点の効果とはみなさない |
| 早さ | 段階ごとに、地図の会社の株価の動き始め（付録 A.1 と同じ定義）までの日数 |
| H5 の後半 | Value Turn の候補のうち、T1 が P1（追い風）の会社と P2（自力）の会社で、改善の続き方を比べる（既存の記録と `evaluate`） |

## 10. 既存の部品の使い回し [推論]

- 会社の文書（有価証券報告書の節）：`edinet.py`・`collect.py`・`docstore.py`（`Company.mentioned_in` で別の会社の文書を防ぐ）
- 一次の足切り：`screener.py`（`Screener.from_config`）。キャッシュは月 1 回の `fetch` のもの。週 1 回の株価は `yf.download` で全銘柄約 1 分の見込み（付録 A.2）
- 二次の調査・引用の照合・品質の関門：`review.py`・`verify.py`・`review_eval.py`（主のモデルは DeepSeek）
- 呼び出しの間隔：`throttle.py`
- 記録と答え合わせ：`records.py`・`outcomes.py`（`evaluate`）
- 通知：`portfolio_arena` は Gmail の SMTP で週次の通知を送っている（同じ形にできる）

## 付録 A. 根拠の詳細

### A.4 業種単位の上方修正の網の過去の採点 [データ：2026-10-18、`portfolio_arena` の `jq_summary`・`jq_bars`・`jq_master`、開示 〜2026-06-12]

問い：ある業種で営業利益の上方修正が急に増えたあと、その業種の株価は市場平均に勝ったか。定義は計算の前に決め、結果を見て変えていない。

| 項目 | 定義 |
|---|---|
| 修正 | 同じ会社・同じ決算期の予想営業利益（連結、無ければ個別。決算短信の当期・翌期の予想と業績修正）が、前回の予想から 5% 以上変わったもの。上方 33,686 件、下方 37,672 件 |
| 業種の幅 | 直近 13 週の（上方 − 下方）の件数 ÷ その週に株価のある業種の会社数 |
| 合図 | 業種の幅の 13 週前からの増加 |
| 業種 | J-Quants の 17 業種（「その他」を除く）。銘柄 5,009 |
| 比べ方 | 13 週ごと（26 週の場合は 26 週ごと）に、合図の上位 3 業種と下位 3 業種を比べる。合図の週の 1 週後の終値から、13 週・26 週の業種の株価（等加重、分割調整）の、全銘柄（等加重）に対する超過の対数リターン。開始の週を 13 通り（26 通り）ずらし、それぞれの t 値を出す |
| 期間 | 合図の週 2010〜2025 年 |
| 比べる相手 | 業種の直近 13 週の超過リターン（株価の勢い） |

| 指標 | 期間 | 上位 3 業種の超過 | 下位 3 業種の超過 | 差 | 差が正の割合 | t 値（中央値、最小〜最大） |
|---|---|---|---|---|---|---|
| 合図 | 13 週 | −0.26% | −0.43% | +0.17% | 51% | 0.30（−0.77〜1.31） |
| 合図 | 26 週 | +0.09% | −1.06% | +1.15% | 57% | 0.98（−1.33〜2.07） |
| 勢い | 13 週 | +0.17% | −0.64% | +0.81% | 53% | 1.14（0.02〜1.92） |
| 勢い | 26 週 | +0.13% | −1.18% | +1.32% | 57% | 0.82（−0.61〜2.00） |

- 前半（2010〜2017）と後半（2018〜2025）に分けると、合図の 13 週の差は −0.21% と +0.56%、26 週は +0.74% と +1.56%。前半では効いていない
- 合図と勢いの順位の相関は 0.09（ほぼ別物）
- 株価と業種は普通株（コードの 5 桁目が 0）だけを使い、株価の表の重複行（2026-05-01〜05-22 の 54,057 行。値は同じ）を除いた。同じ計算を 3 回流して出力が一致した。計算の手順書きは保存していない（使い捨ての分析。上の定義で再現できる）

読み方 [推論]：

- **17 業種の単位では、上方修正の急増は、半年先の業種の超過リターンをはっきりとは予測しない。** 26 週の差 +1.1% は正だが、t 値は 1 前後で、開始の週によって負にもなる。株価の勢いより強くもない
- 理由の候補：17 業種は粗すぎる（セキュリティは「情報通信・サービスその他」の大きな業種の一部で、テーマが平均に埋もれる）。業種の全銘柄の平均を買う形なので、修正した会社とそうでない会社が混ざる
- このため、業種単位の上方修正の網は**使わない**（9 章）。会社単位の上方修正の効果は別の話で、`portfolio_arena` の Guidance Beat が扱っている（その結果はここでは確かめていない）

### A.6 段階 0：過去の制度の追い風で、確定の前後のどこで超過リターンが出たか [データ：2026-10-18、`portfolio_arena` の `jq_bars`（〜2026-06-12）]

**選び方の偏り**：出来事も恩恵銘柄も、後から振り返って選んだ（関連銘柄としてよく挙がる会社）。Tailwind Watch が選ぶ会社（足切りを通る割安な会社）とは違う。出来事は 5 件だけで、統計的な結論は出せない。仕組みの前提（確定の段階で入れば間に合うか）を確かめるためのもの。

| 出来事 | 確定の日 | 根拠 | 恩恵銘柄（コード） |
|---|---|---|---|
| 新紙幣 | 2019-04-09（発表）。発行 2024-07-03 | [報道] | 6457、6418、6428、6430、7991 |
| 防衛 3 文書 | 2022-12-16（閣議決定、5 年で 43 兆円程度） | [一次：防衛白書] | 7011、7012、7013、6208、6203、7721、6946、4274 |

計算：銘柄ごとの日次の超過対数リターン（分割調整、普通株、全銘柄の等加重の平均に対して）を期間で足し、恩恵銘柄で平均した。2 回流して出力が一致。

|---|---|---|---|---|

読み方 [推論]：

- **確定の日に買って 1 年持つと、5 件すべてで市場に負けた。** 2 年持って勝ったのは防衛だけ（−8.9% のあと +48.9%）
- 防衛とサイバーは、確定の前の 1 年で +27〜32% 上がっていた（防衛は確定の前の年にロシアのウクライナ侵攻があった）。確定は遅い
- 新紙幣・自治体・省エネは、確定の前にも後にも、恩恵銘柄が市場に勝っていない。**制度が需要を作っても、目立つ恩恵銘柄の株価は上がるとは限らない**

8 章の関門の基準（「案」より前に株価が動き切っている出来事が大半なら見直す）に照らすと：前に動き切ったのは 2 件で大半ではない。しかし残りの 3 件は前にも後にも上がっておらず、**確定の段階で入る設計（D1・D2 の通知の時点）を支える出来事は 1 件も無かった**。関門は通らなかったと判断し、実装に進まずユーザーに報告する。
